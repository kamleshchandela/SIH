## 2. In-Depth Analysis: BUG-01 (Snapdragon 765G CPU & SurfaceFlinger Choke)

### Problem Description
When running the debug build of `themis_app` on a Google Pixel 4a 5G (Qualcomm Snapdragon 765G, 8 cores, Android 11), the device experienced extreme lag:
- System notification center pulled down with severe stutter.
- App idle CPU utilization hovered between **35% and 55%**.
- Android `surfaceflinger` was pegged at **20% to 30% CPU** continuously, even with zero user interaction.

### Forensic Telemetry (`top` capture during bug):
```text
Tasks: 677 total,   2 running, 675 sleeping
800%cpu 100%user   3%nice  67%sys 619%idle
   PID USER         S[%CPU]  ARGS           
  1833 system        55.5%   system_server
   561 system        19.4%   surfaceflinger
 29089 u0_a398       16.6%   gov.doca.themis_app (Flutter debug)
  2909 u0_a194       11.1%   com.android.launcher3
```

### Technical Root Causes
1. **Unconditional 60 FPS Repaint Loop**:
   [`FluidBackground`](file:///home/arch/Projects/backbone/themis_app/lib/widgets/glass/fluid_background.dart) had an active `AnimationController.repeat(reverse: true)` animating 5 large `ImageFiltered(blur: 75)` circles across the screen. This loop ran continuously even when a static wallpaper image was displayed in front of it.
2. **BackdropFilter Invalidation Storm**:
   Every frame generated by the background forced every single `GlassContainer` card with a `BackdropFilter` to read the entire screen framebuffer into an offscreen buffer, execute a two-pass Gaussian blur shader, and composite it back. With 4 to 8 cards visible, this caused dozens of offscreen passes per frame (3,600+ offscreen passes/minute).
3. **Vulkan CPU Validation Layers in Debug Mode**:
   Android logcat confirmed:
   ```text
   vulkan : added global layer 'VK_LAYER_KHRONOS_validation'
   ```
   On Android 11 with Qualcomm Adreno 620 drivers, the Khronos Vulkan validation layer intercepts every single draw call, pipeline barrier, and descriptor update to perform CPU-side validation checks. Combining 60 FPS backdrop invalidations with CPU Vulkan validation completely saturated the Snapdragon 765G's performance cores.

### Engineering Resolution
1. **Lifecycle & Wallpaper State Gating**:
   ```dart
   void _syncAnimationState() {
     // ONLY run 60 FPS animation loop if Dynamic Fluid Mesh is explicitly active!
     if (_wallpaperService.isMeshSelected && widget.animate) {
       if (!_controller.isAnimating) _controller.repeat(reverse: true);
     } else {
       if (_controller.isAnimating) _controller.stop(); // 0% CPU at idle
     }
   }
   ```
2. **Radial Gradient Shader Stops**:
   Replaced expensive `ImageFiltered(blur: 75)` passes in dynamic mesh mode with native radial gradient color stops (`RadialGradient(stops: [0.0, 0.42, 1.0])`), requiring zero additional GPU blur passes.
3. **AOT Release Compilation**:
   Compiled using `flutter build apk --release`, which strips all debug assertions, disables JIT compilation, and removes `VK_LAYER_KHRONOS_validation`.

### Verified Post-Fix Telemetry:
```text

800%cpu:   > 770% idle

   PID USER         S[%CPU]  ARGS           
  1833 system        3.7%    system_server
   561 system        0.3%    surfaceflinger
 10729 u0_a398       0.0%    gov.doca.themis_app  <-- 0% CPU AT IDLE!
```

## 3. In-Depth Analysis: BUG-02 (Android Gallery Crash & SAF Resolution)

### Problem Description
On certain Android 11 ROMs and devices with modified media providers, triggering the standard image picker (`ImagePicker.pickImage(source: ImageSource.gallery)`) resulted in screen flickering, system memory pressure, and spontaneous crashes of the gallery process.

### Technical Resolution
Implemented a dual-channel input architecture:
1. **Direct Camera Scan**: Captures packaging panels directly via native camera hardware.
2. **Crash-Proof Native SAF Picker**:
   Integrated Android's native **Storage Access Framework (SAF)** via [`FilePicker.pickFiles`](https://pub.dev/packages/file_picker):
   ```dart
   Future<void> _pickNativeFile() async {
     final files = await FilePicker.pickFiles(
       type: FileType.custom,
       allowedExtensions: ['jpg', 'jpeg', 'png', 'webp'],
     );
     if (files.isNotEmpty && files.first.path != null) {
       setState(() => _singlePanelPath = files.first.path);
     }
   }
   ```
   SAF opens the core system document provider (`com.android.documentsui`), which operates in a sandboxed, low-overhead process that completely bypasses vendor gallery application crashes.

## 4. In-Depth Analysis: BUG-03 (Release Network Operation Block)

### Problem Description
After deploying the release APK, tapping **Run Legal Metrology Audit** failed instantly with:
```text
DioException [connection error]: The connection errored: Connection failed
Error: SocketException: Connection failed (OS Error: Operation not permitted, errno = 1), address = localhost, port = 8080
```

### Root Cause
1. **Debug vs Release Manifest Merging**: In Flutter, `android.permission.INTERNET` is included by default in the debug source set (`android/app/src/debug/AndroidManifest.xml`) to support hot reload and DevTools. However, the release manifest (`android/app/src/main/AndroidManifest.xml`) did not explicitly declare it.
2. **Cleartext Traffic Policy**: Android 9 (API 28) and above blocks unencrypted HTTP traffic by default. Because the local PARAKH backend daemon listens on `http://localhost:8080`, Android's network security policy blocked socket creation.

### Resolution
Updated [`themis_app/android/app/src/main/AndroidManifest.xml`](file:///home/arch/Projects/backbone/themis_app/android/app/src/main/AndroidManifest.xml):
```xml
<manifest xmlns:android="http://schemas.android.com/apk/res/android">
    <uses-permission android:name="android.permission.INTERNET" />
    <uses-permission android:name="android.permission.ACCESS_NETWORK_STATE" />

    <application
        android:label="themis_app"
        android:name="${applicationName}"
        android:icon="@mipmap/ic_launcher"
        android:usesCleartextTraffic="true">
```

## 5. In-Depth Analysis: BUG-04 (Frosted Blur Refinement & Readability)

### Problem Description
To isolate the initial GPU churn bug, `enableBlur` was temporarily set to `false` across all cards. While this lowered GPU usage, it left cards completely transparent without frosted diffusion. Against detailed wallpapers (such as `frostedglass.png` ice crystals), background lines interfered with small text, violation tables, and telemetry tags.

### Resolution
With the 60 FPS animation loop paused on static backdrops, `BackdropFilter` can run safely with zero idle overhead.
- In [`GlassContainer`](file:///home/arch/Projects/backbone/themis_app/lib/widgets/glass/glass_container.dart):
  - Set `enableBlur = true` by default.
  - Increased `blur` from `16.0` to **`20.0`** (+25% increase).
- Result: Background patterns are softly diffused into a physical frosted glass texture, ensuring all typography, buttons, and status icons maintain high contrast and compliance readability.

## 6. In-Depth Analysis: BUG-05 (Wallpaper Asset Optimization)

### Problem Description
The original wallpapers in `neo/redesign/wallpaper/` included uncompressed photographic renders up to **71.2 MB** (`crystalbehindgassmonochrome.png`) and **11.4 MB** (`circlecrystal.png`), creating an initial asset footprint of **97 MB**. On mobile devices, decoding a 71 MB uncompressed PNG into an uncompressed RGBA bitmap caused out-of-memory (OOM) crashes and frame drops during startup.

### Resolution
Compressed all 12 assets using lossless/near-lossless optimization:
- `crystalbehindgassmonochrome.png`: 71.2 MB $\rightarrow$ **432 KB** (99.4% reduction)
- `circlecrystal.png`: 11.4 MB $\rightarrow$ **646 KB** (94.3% reduction)
- `frostedcrystalsunset.png`: 5.9 MB $\rightarrow$ **671 KB** (88.6% reduction)
- `frostedglass.png`: 2.8 MB $\rightarrow$ **393 KB** (85.9% reduction)
- **Total Asset Footprint**: Reduced from **97 MB** down to **5.2 MB** across all 12 presets, ensuring instant decoding and zero frame drops on high-DPI displays.
